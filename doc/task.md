# Описание задачи проекта

## Постановка задачи

Проект направлен на прогнозирование вероятности страхового случая (CLAIM_PAID) для полисов страхования транспортных средств.

Целью является разработка полного MLOps-конвейера, включающего этапы:
- загрузка данных
- анализ качества данных
- генерация признаков
- обучение моделей
- оценка качества моделей
- система инференса

---

## Источник данных

Используется набор данных страховых полисов, содержащий информацию о:
- параметрах страхового договора
- характеристиках транспортного средства
- страховой премии
- страховой сумме
- факте страховой выплаты (целевой признак CLAIM_PAID)

Данные загружаются из CSV-файлов и сохраняются в SQLite как слой сырых данных.

---

## Подход к анализу качества данных

В проекте реализованы следующие проверки качества данных:

- полнота данных (доля пропусков)
- корректность значений (бизнес-ограничения, например отсутствие отрицательных значений)
- уникальность записей (поиск дубликатов)
- точность (проверка диапазонов значений, например годов выпуска)
- согласованность временных данных

---

## Признаковое преобразование

В рамках feature engineering создаются дополнительные признаки:

- длительность страхового периода (INSR_DURATION_DAYS)
- год начала действия полиса (INSR_BEGIN_YEAR)
- месяц начала действия полиса (INSR_BEGIN_MONTH)

Данные признаки формируются на основе временных полей исходного датасета.

---

## Архитектура модели

В проекте используются две модели:

- RandomForestClassifier (ансамблевая модель на основе деревьев решений)
- MLPClassifier (нейронная сеть прямого распространения)

Рассматриваемые гиперпараметры:
- количество деревьев (n_estimators)
- максимальная глубина деревьев (max_depth)
- архитектура скрытых слоёв нейронной сети
- параметры обучения нейронной сети (learning rate, число итераций)

---

## Конвейер обработки данных

Процесс обработки данных включает следующие этапы:

1. загрузка данных из CSV
2. сохранение в SQLite (raw layer)
3. очистка данных
4. генерация признаков
5. разделение на обучающую и тестовую выборки
6. обучение моделей
7. оценка качества моделей
8. сохранение модели

---

## Оценка качества моделей

Используется метод hold-out валидации с стратифицированным разбиением выборки.

Для оценки качества применяются метрики:
- ROC-AUC
- F1-score
- Precision
- Recall
- отчет классификации

---

## Развёртывание модели

Лучшая модель выбирается на основе ROC-AUC и сохраняется в файл:

models/final_model.pkl

Инференс выполняется через CLI-интерфейс:

python run.py -mode inference -file data/*.csv

---

##CI/CD и архитектура решения

В проекте реализован CI/CD workflow с использованием GitHub Actions.

Выбранный подход использует сценарий итеративного независимого обучения.

Данный подход выбран:
1. модель работает с регулярно обновляемыми данными, что требует периодического переобучения;
2. требуется автоматизация полного ML pipeline через CI/CD без участия пользователя;
3. обеспечивается регулярное обновление модели при сохранении стабильности и изоляции запусков;
4. каждый запуск обучения является независимым и воспроизводимым экспериментом.
